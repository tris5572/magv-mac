## 1. 目的と仕様の読み方

magvの漫画閲覧体験を維持し、Swiftで実装したmacOSネイティブアプリへ移植する。現行アプリもmacOS向けであるが、画面と閲覧処理の中心はTauri上のReact／TypeScriptで構成されている。移植後はSwiftUI／AppKitで画面を構成し、閲覧にWebView、JavaScriptランタイム、WASMを使用しない。

本書では以下を区別する。

| 表記 | 意味 |
| --- | --- |
| 現行 | 調査対象コミットのコードから確認した動作。実機での動作確認は未実施 |
| 移植必須 | 初期ネイティブ版で維持・実装する要件 |
| 改善 | 不具合防止またはmacOSへの適合のため、本書で追加する要件 |
| 推奨・暫定 | 技術選定、数値目標、配布方針など、実装前に確定する提案 |
| 対象外 | 初期移植の完成条件に含めない機能 |

READMEの「将来の機能追加予定」はコードと一致していない。単体表示、左開き、画像ファイル表示、メニュー、表示切替、スライドショーはすでにコードに存在するため、移植対象に含める。

## 2. 対象範囲と実行環境

### 2.1 初期版の対象

- ZIP／RAR、画像ファイル、画像フォルダを開く。
- 単体表示／自動見開き、右開き／左開き、ページ移動を提供する。
- 同階層の前後ソースへの切替、ランダム切替を提供する。
- ページインジケーター、ルーペ、スライドショーを提供する。
- アーカイブのリネーム、名前の先頭への`!`追加、ファイル名検索を提供する。
- メニュー、最近使った項目、ウィンドウ位置・サイズの復元を提供する。
- 読み込み失敗、権限不足、名前変更失敗を日本語で通知する。

### 2.2 推奨環境と配布

| 項目 | 初期案 |
| --- | --- |
| 対応OS | macOS 26以降程度 |
| CPU | Apple Silicon |
| 言語・UI | Swift、SwiftUI、必要箇所にAppKit |
| 表示言語 | 日本語 |
| ウィンドウ | 閲覧用は1つ。新規オープンは同じウィンドウの内容を置換 |
| 通信 | ローカル閲覧は完全オフライン。明示的な検索操作のみ既定ブラウザを開く |
| 配布 | まずは自分で使えるだけで良い。将来的にはDeveloper ID署名・公証付きアプリの直接配布を行う可能性はある。App Store対応は別途判断 |
| 識別子 | 移植検証中は既存と異なるBundle IDを使用。正式な値は未決定 |

### 2.3 初期版の対象外

PDF、EPUB、7z、CBZ／CBRの拡張子追加、クラウド同期、本棚・タグ管理、OCR、画像編集、アーカイブの作成・再圧縮、アーカイブ内のアーカイブ、パスワード入力、分割アーカイブ、フォルダの再帰走査、ショートカットの自由編集、分類移動、複数閲覧ウィンドウ。アニメーション画像は初期版では先頭フレームの静止表示とする改善案であり、現行のブラウザ描画との差分として扱う。

## 3. 現行構成と移植対応

| 現行の担当 | 主なファイル | ネイティブ版の対応 |
| --- | --- | --- |
| UI・アプリメニュー・イベント登録 | `src/components/App.tsx` | SwiftUI、NSWindow、NSMenu、入力ルーター |
| 画像描画・見開き配置 | `ImageView.tsx`、`SingleImageView.tsx` | AppKitの画像キャンバス、SwiftUIの画面構成 |
| 閲覧状態・ソース切替・履歴 | `src/atoms/source.ts`、`app.ts` | ReaderSession、SourceLoader、SessionHistory |
| キー割当と方向反転 | `src/atoms/config.ts`、`event.ts` | ReaderCommand、InputRouter |
| ページ移動規則 | `src/utils/pages.ts` | UI非依存のPageNavigator |
| ファイル列挙とリネーム | `src/utils/files.ts` | FoundationのURL／FileManager |
| ZIP／RAR展開 | `src/utils/archive.ts` | ArchiveReaderの背後にネイティブライブラリ |
| ウィンドウ復元 | `src-tauri/src/lib.rs`、`src/hooks/config.ts` | NSWindow、WindowStateStore |

現行ではZIPをfflate、RARをnode-unrar-jsのWASMで展開する。ネイティブ版ではこれらを置換する。Rust側にファイル一覧用コマンドも存在するが、調査した閲覧経路はTypeScript側の列挙・展開処理を使用している。

## 4. ファイルを開く仕様

### 4.1 対応形式

| 種類 | 移植必須の拡張子・範囲 |
| --- | --- |
| アーカイブ | `.zip`、`.rar`（大文字小文字を区別しない） |
| 画像 | `.jpg`、`.jpeg`、`.png`、`.gif`、`.bmp`、`.webp` |
| フォルダ | 直下の対応画像のみ。子フォルダを再帰走査しない |

拡張子判定後に実データを検証する。拡張子だけが対応形式の破損ファイルはエラーにする。HEIC／TIFF等を表示可能であれば、対応拡張子として含める。WebPを含む全形式のデコード可否は対応OS上の受け入れテストで確認する。

### 4.2 開く入口

- **移植必須:** Finderからウィンドウへのドロップ。ウィンドウ内およびアイコンへのドロップに対応する。現行同様、複数項目は先頭1件のみ開く。
- **移植必須:** 最近使った項目から開く。
- **改善:** `⌘O`と「ファイルを開く」でNSOpenPanelを表示し、対応ファイルまたはフォルダを1件選択する。現行ではこのメニューは無効。
- **改善:** Finderの「このアプリケーションで開く」とDockへのドロップに対応する。画像の既定アプリを自動変更しない。
- オープン失敗または選択キャンセル時は、現在の閲覧内容を維持する。

### 4.3 ソース生成と並び順

1. アーカイブの場合、内部の全階層から対応画像を列挙する。内部フォルダの画像は含めるが、入れ子の圧縮ファイルにも可能であれば対応する。
2. アーカイブではディレクトリエントリ、非対応画像、ルートの`__MACOSX/`配下を除外する。改善としてAppleDoubleファイル（`._`で始まる名前）も除外する。
3. 画像／フォルダの場合、画像のあるフォルダ直下を列挙し、`.`で始まるファイルを除外する。
4. 数値を考慮した自然順で並べる。`1.jpg, 2.jpg, 10.jpg`の順になること。アーカイブ内は内部相対パス全体を比較する。
5. ネイティブ版は`localizedStandardCompare`を基本とし、比較結果が同順位の場合は元の文字列で決定的に並べる。JavaScriptの`localeCompare`との完全一致は保証せず、日本語・英数字の固定サンプルで差を確認する。
6. 画像ファイルを直接指定した場合は、その画像を起点に表示する。ソースの識別・履歴は所属フォルダ単位とする。
7. アーカイブ／フォルダを初めて開いた場合は先頭から、起動中に再度開いた場合は最後の閲覧インデックスから表示する。
8. 開いたソース名をウィンドウタイトルに設定する。アーカイブは拡張子付きのファイル名、画像／フォルダはフォルダ名。

画像0件は「表示できる画像がありません」と通知し、現在の表示を維持する。現行の空ZIP／RARと空フォルダの不統一は引き継がない。

### 4.4 読み込み中の状態

`未読込 → 読込中 → 閲覧中`を基本とし、失敗時は以前の閲覧中状態または未読込状態へ戻る。読込中は進捗表示とキャンセル操作を提供する。新しいオープン要求を受けたら古い要求を取り消し、要求IDが最新の結果だけを画面に反映する。

正常オープン時はスライドショーを停止し、リネーム入力を閉じる。画像リスト、タイトル、兄弟ソース、履歴を一括更新し、異なるソースの状態が混ざらないようにする。

## 5. 表示とページ移動

### 5.1 基本表示

- 初期値は「見開き」「右開き」。設定ファイルに状態を保存し、再起動時は引き継ぐ。
- 画像の縦横比を維持し、全体が表示領域に収まるよう拡大縮小する。画像の切り抜きは行わない。
- 画像領域は暗い背景とし、下端のインジケーター領域を除いた範囲を使う。
- 見開きは左右に同じ幅の領域を割り当て、中央の綴じ側に画像を寄せる。
- 右開きでは若い番号を右、次の画像を左に表示する。左開きでは逆にする。
- ウィンドウの縦横比を理由に表示モードを自動変更しない。
- 先頭の表紙を自動的に単体表示する特例は設けない。先頭2枚が縦長なら見開きになる。

### 5.2 見開き判定

内部インデックスは0始まり、ユーザー向けページ番号は1始まりとする。現在表示の最小インデックスを`i`、総画像数を`N`とする。

- 縦長: EXIF等による向き補正後の幅が高さ未満。
- 横長扱い: 幅が高さ以上。正方形も単体表示。
- 単体モード、強制単体指定、または`i+1`が存在しない場合は`i`だけ表示。
- それ以外は`i`と`i+1`の両方が縦長のときだけ2枚表示。
- 向き取得失敗を縦長として推測しない。画像エラーの代替表示を1枠で表示する。

向き補正の扱いはネイティブ版の明示仕様。現行はブラウザから得た画像の自然サイズを使っており、EXIF全パターンの一致は未検証。

### 5.3 ページ移動規則

| 操作 | 移植後の規則 |
| --- | --- |
| 次ページ | 現在単体なら`i+1`、見開きなら`i+2`から見開きを再判定 |
| 前ページ（単体モード） | `i-1`を表示 |
| 前ページ（見開きモード） | `i-1`と`i-2`が両方縦長なら`i-2`から見開き。それ以外は`i-1`を強制単体表示 |
| 1枚次へ | `i+1`から見開きを再判定。すでに最後の画像を含む単体／見開きを表示中なら移動しない |
| 1枚前へ | `i-1`から見開きを再判定 |
| 最初へ | インデックス0から見開きを再判定 |
| 最後へ | 単体モードは`N-1`。見開きモードで末尾2枚が縦長なら`N-2`、それ以外は`N-1` |
| 直接指定 | 指定インデックスから見開きを再判定 |
| 表示モード／方向変更 | インデックスを維持して表示を再計算 |

前ページで強制単体にするのは、移動前の画像を再び見開きに含めないためである。例えば`縦・横・縦`の3枚目から戻ると2枚目のみ、`横・縦・縦`の3枚目から戻ると2枚目のみを表示する。

すべての操作で先頭・末尾を越えず、ページ端から別ソースへ自動移動しない。ページ番号を先頭へループさせない。`N=1`の「最後へ」はページ0の表示を維持する。

### 5.4 ページインジケーター

- 下端に高さ32pt程度相当の領域を設ける。
- 現行互換で`i+1 / N`を表示する。見開きでも若い番号だけを表示する。
- 未読込時は`- / -`。
- 進捗色は右開きで右から左、左開きで左から右に伸びる。
- クリック／ドラッグで任意位置へ移動する。
- 座標はバー内の相対位置を用い、右開きでは反転する。移動先は`floor(比率×N)`を`0...N-1`に補正する。
- `N=0`は操作不可、`N=1`の進捗は100%とし、ゼロ除算を防止する。
- VoiceOver用に現在ページと総画像数、増減操作を提供する。

## 6. ソースの切替と履歴

### 6.1 前後・ランダム

- アーカイブ閲覧中: 同じ親フォルダのZIP／RARを自然順で列挙し、前後の候補にする。
- 画像／フォルダ閲覧中: 現在フォルダと同じ親を持つ兄弟フォルダを自然順で列挙する。
- 上キーで前、下キーで次。先頭／末尾では何もしない。循環しない。
- 画像を含まない兄弟フォルダを選んだ場合は通知し、現在の表示を維持する。自動で次の候補へ飛ばさない。
- `r`は現在以外の兄弟ソースからランダムに1つ選ぶ。コード上はアーカイブだけでなく画像／フォルダにも同じ切替処理が適用されるため、これを移植する。
- 候補なしは操作不可。候補が移動・削除されていたら一覧を更新する。
- ランダム選択は有効候補から直接選び、現行の最大100回の再抽選方式は引き継がない。

### 6.2 履歴

| データ | 保持期間・規則 |
| --- | --- |
| 最終閲覧位置 | アプリプロセスの起動中のみ。アーカイブURLまたはフォルダURL単位 |
| 最近使った項目 | 起動中のみ。最新が先頭、重複なし、最大20件 |
| 表示モード・開き方向 | 起動中のみ |
| ルーペ有効状態 | 起動中のみ、初期値OFF |
| スライドショー間隔 | 起動中のみ、初期値5.0秒 |
| ウィンドウ位置・サイズ | 再起動後も保持 |

通常のウィンドウ閉鎖でプロセスが残る場合はセッション履歴も残す。`⌘Q`等で終了したら閲覧履歴を消去する。起動時に前回の本を自動で開かない。

外部更新で画像数が変わった場合は保存インデックスを有効範囲に補正する。リネーム成功時は履歴・キャッシュ・兄弟一覧の識別情報を新URLへ移す。

## 7. 入力仕様

### 7.1 キーボード

| キー | 右開き | 左開き |
| --- | --- | --- |
| `←` | 次ページ | 前ページ |
| `→` | 前ページ | 次ページ |
| `Shift+←` | 1枚次へ | 1枚前へ |
| `Shift+→` | 1枚前へ | 1枚次へ |
| `⌘←` | 最後へ | 最初へ |
| `⌘→` | 最初へ | 最後へ |
| `Home` | 最後へ | 最初へ |
| `End` | 最初へ | 最後へ |
| `Space` | 次ページ | 次ページ |
| `Shift+Space` | 前ページ | 前ページ |
| `↓`／`↑` | 次／前ソース | 次／前ソース |
| `r` | ランダムソース | ランダムソース |
| `Return` | リネーム入力を開く（アーカイブのみ） | 同左 |
| `!` | 先頭に`!`を追加 | 同左 |
| `f` | ソース名をWeb検索 | 同左 |
| `⌘O` | 開く（改善） | 同左 |
| `⌘W` | ウィンドウを閉じる（改善） | 同左 |
| `⌘Q` | アプリ終了 | 同左 |

Home／Endも方向に応じて反転する現行規則を維持する。`!`は文字として解釈し、キーボード配列ごとの物理キーに固定しない。

テキスト入力中・日本語変換中は閲覧ショートカットを発火させない。イベント処理はメニューと画面側で重複実行しない。未読込時の閲覧コマンドは無効化する。

### 7.2 マウス・トラックパッド

- 縦ホイールの正方向を次ページ、負方向を前ページへ対応付ける。開き方向では反転しない。
- 現行はホイールイベントごとに移動する。改善としてトラックパッドの微小移動・慣性で大量にページ送りしないよう、累積量・ジェスチャー終了・待ち時間を使って抑制する。閾値は試作で調整する。
- 横スクロール／ピンチズームは初期版では割り当てない。
- 中ボタンクリックでルーペON／OFF。
- 右クリックで次／前／最初／最後のページ、フルスクリーンのメニューを表示する。
- 通常の画像左クリックにはページ送りを割り当てない。
- ファイルオープン・ページ移動・ソース切替で画像領域のカーソルを隠し、マウス移動で再表示する。
- 入力欄、メニュー、エラー表示、他アプリへ移動するときはカーソルを確実に表示する。

## 8. 画面とメニュー

### 8.1 画面構成

```text
┌─────────────────────────────────────────┐
│ 標準タイトルバー：アーカイブ名／フォルダ名       │
├─────────────────────────────────────────┤
│ 上端ホバー：単体/見開き・右/左開き・自動再生/間隔 │
│                                         │
│            画像キャンバス／見開き            │
│             読込中表示・ルーペ              │
│                                         │
├─────────────────────────────────────────┤
│         ページ移動バー     1 / 120          │
└─────────────────────────────────────────┘
```

未読込時は対応形式とドロップ案内、「開く」ボタンを表示する。リネームはシートまたは中央の入力パネル、一般エラーは通知またはアラートとする。現行の開発用ログ表示を製品の通常画面へ持ち込まない。

上端ホバーで操作部を表示する現行体験を維持する。同じ操作をメニューからも実行できるようにし、キーボード・VoiceOver利用者がホバーに依存しないようにする。

### 8.2 メニュー

| メニュー | 項目 |
| --- | --- |
| magv | このアプリについて、非表示、ほかを非表示、すべてを表示、終了 |
| ファイル | 開く、最近使った項目、名前を変更、先頭に!を追加、ウィンドウを閉じる |
| 編集 | テキスト欄の標準Undo／Redo、切り取り、コピー、貼り付け、すべて選択 |
| 表示 | 単体／見開き、右開き／左開き、ルーペ、自動再生開始／停止、再生間隔 |
| 移動 | 次／前ページ、1枚次／前、最初／最後、次／前ソース、ランダム |
| ウィンドウ | フルスクリーン、拡大／縮小、最小化 |

ネイティブ版では「このアプリについて」を有効化する。設定画面は初期版対象外とし、現行の無効な「設定」メニューは表示しない。現行の`⌘W`は空の処理なので標準の閉じる操作へ修正する。

チェック状態は表示状態と同期する。名前変更はアーカイブ時のみ有効。ページ端、未読込、兄弟候補なしでは該当移動項目を無効化する。テキスト編集用Undoはファイル名変更のUndoを意味しない。

メニュー項目はMacのアプリとして他にもあった方が適切な項目は存在して構わない。

## 9. 補助機能

### 9.1 ルーペ

- 初期値OFF。中クリックおよび表示メニューで切替可能とする。
- 現行の基準値は600×600のレンズ、表示画像に対して8倍。移植案では600×600pt、8倍を初期値とする。
- カーソル位置の実画像座標を拡大中心とする。余白、見開きの左右配置、Retina倍率、ウィンドウサイズ変更を考慮する。
- 画像外では表示しない。見開きではカーソルが乗っている画像だけを参照する。
- レンズは画像領域でクリップし、入力・ページバーを妨げない。描画はポインターイベントを消費しない。
- 表示用に縮小した画像だけでなく、必要に応じて高解像度データを使い文字の判読性を保つ。

### 9.2 スライドショー

- 初期間隔5.0秒。現行UIに合わせ、0.5～100,000秒、0.5秒刻み。
- 空欄、非数、0以下、範囲外は受け付けず、入力エラーを表示する。
- 1間隔で「次ページ」コマンドを1回実行する。見開き／単体モードに従う。
- 手動ページ移動、直接指定、表示再計算で経過時間をリセットする。
- ソース切替、停止ボタン、最終画像を含む表示への到達で停止する。最後から次の本へ進めない。
- 改善として、最終ページでの開始を無効化し、画像読込失敗・リネーム開始・ウィンドウ閉鎖でも停止する。
- OSスリープ復帰時に未処理のページ送りを連続実行しない。タイマーは単調時間を基準とし、完了済みのページ送りから次の待機を開始する。
- 間隔変更時は経過を0にして新しい間隔で待つ。現行の100ms刻みカウントによる時間ずれは互換対象外。

### 9.3 リネームと!付与

- 通常リネームはZIP／RARのみ。元ファイルの拡張子を保持して名前本体だけ変更する。
- 入力開始時に現在名を選択し、前後ソース名を補助表示する。
- Returnで実行、Escでキャンセル。日本語変換確定のReturnを実行と誤認しない。
- 同名入力は何もしない。空名、`.`、`..`、パス区切り、NUL等の不正な入力は拒否する。
- 同名ファイルが存在する場合は名前本体の末尾に`_`を追加し、空いている名前まで繰り返す。例: `book.zip → new.zip`が競合したら`new_.zip`。
- `!`は名前の先頭へ1文字追加する。既存の`!`を取り除くトグルにはしない。
- 現行の`!`付与処理には画像／フォルダの制限がないが、移植版では通常リネームと同じくアーカイブだけに制限する改善案とする。
- `a.b.zip`のような複数ドットでも最後の拡張子のみ分離する。競合回避で名前の一部を失わない。
- 変更成功後にタイトル、履歴、キャッシュ、兄弟一覧、前後候補を一括更新する。
- 変更失敗時は入力を保持し、理由を表示する。既存ファイルを上書きしない。候補名確認後の競合も安全に再試行する。
- ファイル本体は移動しない。アーカイブ内容を再圧縮しない。

### 9.4 名前検索

- `f`またはメニューから現在ソース名をDuckDuckGoで検索し、既定ブラウザで表示する。
- アーカイブは最後の拡張子を除いた名前、フォルダはフォルダ名全体を使用する。
- ASCIIハイフン`-`を空白に変換し、検索語をURLエンコードする。
- URL形式: `https://duckduckgo.com/?t=h_&q=<エンコードした検索語>`。
- アプリ内の説明に「名前をWeb検索」と表記する。ファイル内容は送信せず、検索語のみブラウザへ渡す。
- 未読込・空の検索語は操作不可。現行の短いフォルダ名の拡張子除去誤判定は引き継がない。

## 10. ウィンドウと保存データ

### 10.1 ウィンドウ

- 初期コンテンツサイズは現行同様640×480ptを基準とする。最小サイズは暫定320×240pt。
- サイズと位置を論理座標で保存する。スクリーン座標の原点差を考慮し、Tauriの座標をAppKitへそのまま渡さない。
- モニター切断、Retina倍率変更、メニューバー・Dock、画面より大きい保存サイズを考慮して、表示可能領域へ補正する。
- 復元処理後にウィンドウを表示し、初期位置のちらつきを抑える。
- 設定を適切なタイミングで保存する。
- 壊れた設定、非数、負のサイズ、範囲外の値は無視し、既定値で起動する。
- 閉じる操作はウィンドウを閉じ、Dock再表示／開く要求で再作成する。プロセス終了は`⌘Q`で行うmacOS標準動作を採用する改善案。

### 10.2 永続化

ネイティブ版専用のApplication Support領域へ、バージョン付き設定を原子的に保存する。キャッシュはLibrary/Cachesの専用領域に分離する。閲覧履歴・最近使った項目・画像の永続保存は初期版では行わない。

```json
{
  "schemaVersion": 1,
  "window": {
    "frame": { "x": 100, "y": 100, "width": 640, "height": 480 },
    "coordinateSpace": "appkit-screen-points"
  }
}
```

上記`frame`はネイティブ版のウィンドウ外枠座標の設計例。現行`window.json`は`window.position`と`window.size`を保持し、同一スキーマではない。

既存設定の自動移行は初期版必須としない。追加する場合は`~/Library/Application Support/com.github.tris5572.magv/window.json`を読み取り専用で取り込み、内側サイズ／外枠サイズと座標系を変換する。旧設定を書き換えない。閲覧位置は現行でも永続化されないため移行元がない。

### 11.1 モジュール

| App／WindowCoordinator | 起動、外部ファイルオープン、メニュー、ウィンドウ管理 |
| ReaderSession（MainActor） | 現在ソース、インデックス、表示モード、読込状態の一元管理 |
| InputRouter | キー・ホイール・メニュー操作をReaderCommandへ変換 |
| PageNavigator | 縦横情報から表示インデックスと表示枚数を計算する純粋なロジック |
| SourceLoader | 列挙、ソース生成、要求取消、履歴復元 |
| ArchiveReader | エントリ一覧、画像データ取得、エラー分類 |
| ImageDecoder | Image I/Oでメタデータ取得、向き補正、縮小デコード |
| ImageCanvas（NSView） | 単体・見開き、ルーペ、ポインター、Retina描画 |
| SourceCache（actor） | 容量上限付きキャッシュ、重複要求の共有、更新検知 |
| FileAccessService | アクセス権、リネーム、兄弟ソース列挙 |
| SessionHistory／WindowStateStore | 起動中履歴と永続ウィンドウ状態を分離 |

SwiftUIで周辺UIを構成し、画像描画・マウスイベント・ルーペにはNSViewRepresentableを使う案を推奨する。展開・列挙・デコードはメインスレッド外で実行し、UI反映だけをMainActorで行う。

### 11.2 データモデル

| モデル | 主なフィールド |
| --- | --- |
| SourceID | 正規化URL、必要に応じてファイル識別子 |
| SourceDescriptor | ID、種類（archive／directory）、表示名、親URL、更新日時・サイズ |
| ImageEntry | エントリID、画像名、アーカイブ内相対パスまたはファイルURL、向き・寸法、デコード状態 |
| LoadedSource | SourceDescriptor、順序付きImageEntry配列、兄弟ソース一覧 |
| DisplayPage | anchorIndex、visibleIndices（1件または2件）、強制単体フラグ |
| ReaderState | idle／loading／ready、現在ソース、表示、モード、方向、エラー、最新要求ID |
| SessionHistory | SourceIDごとの最終インデックス、最近使ったID最大20件 |

画像データをすべてモデル内へ常時保持せず、キャッシュを通して必要分を取得する。パス変更に弱い絶対パス文字列だけで状態を結び付けない。

### 11.3 ZIP／RARライブラリ

推奨候補は同梱版libarchiveをSwiftからCブリッジで利用する構成。公式にはZIPおよび従来RAR／RAR v5の読み取り対応が示されている。ただし、採用ビルドとアーカイブ方式による制限があるため、RARの全面互換を事前に約束しない。[対応形式の一次資料](https://github.com/libarchive/libarchive/wiki/LibarchiveFormats)

- 採用バージョンと有効形式を固定し、OS付属コマンドやHomebrewへの依存を避ける。
- ZIPはStored／Deflate、ZIP64、日本語ファイル名をテストする。
- RAR4／RAR5、solid形式、日本語名を含む実ファイル群で検証する。
- 暗号化・分割・未対応圧縮方式は専用エラーを返す。
- ランダムなエントリ取得が高コストなsolid形式では、バックグラウンドで順次展開して上限付き一時キャッシュを使う。
- RAR互換が不足した場合はArchiveReader実装を別のネイティブ展開器へ差し替える。ZIPだけの対応を移植完了とはしない。

Image I/Oによる表示サイズに合わせた縮小デコードを検討し、全解像度の一括展開を避ける。[Appleの画像ソースAPI](https://developer.apple.com/documentation/imageio/cgimagesource)

### 11.4 キャッシュと先読み

現行はアーカイブの画像Blobをパス単位で保持し、前後アーカイブも先読みする。容量上限・外部更新時の失効は明示されていない。

移植版は現在ページと前後ページを最優先とし、隣接ソースはエントリ一覧と最初に表示する画像を低優先度で先読みする。全アーカイブを無制限にメモリへ保持しない。

- 同一ソースへの同時要求は共有し、二重展開しない。
- URL、サイズ、更新日時等で変更を検知しキャッシュを無効化する。
- 暫定上限: メモリ画像キャッシュ256MiB、一時ディスクキャッシュ2GiB。巨大な単一画像も別途上限判定する。
- LRUで削除し、メモリ圧迫時は先読み分から破棄する。
- 先読み失敗は現在ページを失敗扱いにしない。対象を実際に開いた時点で通知する。
- キャンセルされた処理や古い要求の結果は画面へ反映しない。

## 12. ファイルアクセスと安全性

### 12.1 サンドボックス方針

直接配布時にApp Sandboxを有効化するかは未決定。どちらの場合もアクセス権処理をFileAccessServiceへ集約する。

Sandbox有効時は、ユーザーが選択したファイルへの権限だけで兄弟ファイルの列挙や親フォルダ内のリネームが可能と仮定しない。必要時に親フォルダの選択を案内し、未許可でも単体閲覧は可能な限り継続する。読み書き権限・security-scoped URLの開始／終了を処理し、再起動後のアクセスを追加する場合はbookmarkを使用する。[Appleのファイルアクセス資料](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox)、[security-scoped bookmark](https://developer.apple.com/documentation/foundation/nsurl/bookmarkcreationoptions/withsecurityscope)

### 12.2 アーカイブ処理

- 画像閲覧以外では元ファイルを書き換えない。書き込みは明示リネームとアプリ専用設定・キャッシュに限定する。
- 絶対パス、`..`等による専用キャッシュ外への展開を禁止する。シンボリックリンクを展開先として使用しない。
- 暫定上限: エントリ数100,000、単一画像の展開データ256MiB、画像寸法100メガピクセル、1ソースの累積展開量10GiB。実データで検証して調整する。
- ヘッダーの申告サイズだけでなく実際の展開量を監視し、上限到達時は停止して理由を通知する。
- 一時データは専用キャッシュへ作り、通常終了・次回起動時に不要分を清掃する。
- 自動通信・解析データ送信は初期版に含めない。

## 13. エラー時の動作

| 条件 | ユーザー向け動作 |
| --- | --- |
| 未対応形式 | 対応形式を案内。現在の本を維持 |
| ファイル不在・外部移動 | 再選択を案内。兄弟一覧を更新 |
| アクセス権不足 | 必要なファイル／フォルダの選択を案内 |

| 個別画像の破損 | 当該位置をエラー表示し、前後移動を許可。総数と順番は維持 |
| 読込上限超過 | 上限種別を示して停止。現在の本を維持 |

| キャッシュ不足 | 先読みを破棄して再試行し、失敗時は通知 |
| 先読み失敗 | 現在の閲覧を継続 |

## 14. 品質目標と受け入れ条件

## 16. 実装順序と完成判定

1. **形式検証:** ZIP／RAR4／RAR5、solid、日本語名、WebPの試作とライブラリ選定。RAR互換の成立を最初に確認する。
2. **閲覧の核:** SourceLoader、PageNavigator、画像キャンバス、単体／見開き、方向、入力、インジケーター。
3. **日常操作:** 兄弟ソース切替、履歴、メニュー、リネーム、検索、ウィンドウ保存。
4. **補助と品質:** スライドショー、ルーペ、先読み、容量制限、取消、エラー、アクセシビリティ。
5. **配布検証:** 実際の署名・公証済みアプリで外部オープン、権限、依存物の同梱とクリーン環境起動を確認する。

初期版の完成条件は、移植必須機能の実装、A01～A31の適用ケースの合格、RARの対応範囲明示、全依存物の同梱、既存アプリとデータを壊さず併存できることとする。未確定の配布・CPU方針は配布検証前に確定する。
