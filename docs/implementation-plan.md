# ネイティブ移植の進捗

更新: 2026-10-16（日本時間）

原仕様: [native-spec.md](native-spec.md)。原文は変更せず保存し、矛盾の解消や採用した暫定案はこの文書へ記録する。原仕様内の「推奨・暫定」は確定要件と区別する。

## 決定と暫定条件

- **ユーザー確認済み:** 単体／見開き、右／左開きは再起動後も保存する。仕様5.1と6.2の矛盾は前者を採用。現在はネイティブ版専用のUserDefaultsに保存する。閲覧位置・最近使った項目はメモリ内だけに保持する。
- macOS 26以降、arm64、仮Bundle ID `dev.tris.magv-native`。正式な配布・名称・Intel対応は未決定。
- App Sandboxは雛形の有効設定を維持し、選択ファイルへの読み取り権限のみ。兄弟操作やリネームの権限処理は第3段階で試作する。
- 入れ子アーカイブは仕様2.3の対象外を採用する。4.3の「可能であれば」は今回含めない。
- GIF／アニメWebPは先頭フレーム。HEIC／TIFFも拡張子を受け付けるが、追加のデコード検証が必要。

## 現在の構成

- `Packages/MagvCore`: UIに依存しないモデル、自然順、PageNavigator、ファイルアクセス、ArchiveReader、SourceLoader、ImageDecoder、ImageCache。
- `magv-mac/ReaderSession.swift`: MainActor上の閲覧状態。最新要求ID、バックグラウンド作業取消、成功時の一括更新、セッション履歴。
- `magv-mac/ImageCanvas.swift`: AppKit描画、中央の綴じ側への配置、ホイール、右クリック、Retinaに応じたデコード寸法。
- `magv-mac/ContentView.swift`: SwiftUIの空画面、上端ホバー、読込表示、ドロップ、ページバーとVoiceOver増減。
- `magv-mac/MyApp.swift`: アプリ・単一ウィンドウのライフサイクル、NSOpenPanel、NSMenu、外部オープン、テキスト編集を避けた入力ルーティング。
- `Config/Info.plist`: Viewer／Alternateとして形式を宣言。既定アプリの変更処理はない。

## 検証記録

- macOS 27.0.1、Xcode 27.0／Swift 6、arm64。DebugとReleaseの署名なしビルドが成功。最低対応候補のmacOS 26実機では未検証。
- コア18テスト（パラメーター別のケースを含む）とセッションスモークが成功。`./scripts/test.sh`で両方を実行できる。
- PageNavigator: 現行`pages.test.ts`の前ページ混在ケースを移植。0／1枚、正方形扱い、未知の向き、末尾見開き、1枚ずらし、バー端を追加。1～6枚の縦／横／未知の全組合せで全操作の範囲と見開き条件も検査。
- 形式: RAR4（Stored／Normal／Best）とRAR5の展開内容を照合。RAR5 solidの4エントリを生成規則とバイト単位で照合。Unicode名、CP932日本語ZIP、UTF-8日本語ZIP、ZIP64、PNG／WebP／EXIF JPEGを確認。暗号化は専用エラーを確認。ZIPをSourceLoaderで開く全経路と、解放時の一時データ削除も検証。
- 安全性: 不正パス、エントリ数、単一画像サイズ、一時展開サイズ、破損アーカイブを検査。保存先にはUUIDを使い、リンクを展開しない。
- 列挙: 非再帰、隠しファイル除外、1／2／10の自然順、直接画像指定を一時フォルダで確認。
- セッションスモーク: 開いた本の位置復元、直接画像の位置優先、失敗時維持、A→B→CでCの維持、キャンセル、最近使った項目の重複排除／最新順／20件、左右とHomeの方向反転を確認。
- 実画面: 起動、空画面、⌘OのNSOpenPanel、ZIPの見開き、タイトル／ページ数、`←`で1→3、末尾停止、前ページ移動を確認。
- UI自動操作では表示メニューの選択が無効な要素IDを返した。メニュー状態の取得はできたが、選択／チェック同期は未検証。プロセスのサンプルではメインスレッドは通常のイベント待機で、停止は見られなかった。
- この検証は**A01～A31全体の合格を意味しない**。署名とSandboxの権限条件、実漫画／大容量／RAR4 solid、トラックパッド／VoiceOver／IME、Finder／Dock、モニター条件は未検証。

## 現時点の制限

1. アーカイブはバックグラウンドで画像を順次すべて一時展開した後に開く。solid対応の基本経路は成立しているが、先頭表示3秒・先読み・ランダムアクセスの性能調整は未実施。
2. 画像キャッシュは256MiBのLRU。デコードを直列化して急速な操作時の一時メモリ増大を抑制。同一キーの要求を共有し、ファイルURL・更新日時・サイズ・デコード寸法で識別する。メモリ圧迫通知と隣接先読みは未実装。
3. 一時ディスクの2GiB上限は**1回の展開ごと**。ソース切替中は旧ソースと新ソースの一時データが重なる。全体2GiBの管理、異常終了後の清掃は第4段階に残る。通常のソース解放時には専用一時フォルダを削除する。
4. 選択画像の親フォルダが読めない場合は、その画像だけを表示できるようにする。親フォルダ権限の再選択案内と兄弟操作は次段階。権限外の内容を取得できるとは仮定しない。
5. 画像メタデータが読めない位置は単体のエラー枠として残す。既知の巨大寸法・展開量上限超過はソース全体のオープンを中止する。
6. 表示設定はUserDefaultsを使用。仕様10.2のバージョン付きApplication Support JSONとウィンドウ位置の保存は第3段階で統合する。
7. 旧アプリの設定・データ・アイコンは変更・取り込みしていない。移植コードの正式ライセンス、名称、署名、公証は配布前に決める。同梱依存物の著作権表示はアプリの`ThirdPartyNotices.txt`に含める。

次は第3段階を実装し、FileAccessServiceを拡張して、兄弟操作とリネームのための親フォルダ権限処理を一緒に検証する。
