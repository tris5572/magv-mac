## 決定と暫定条件

- **ユーザー確認済み:** 単体／見開き、右／左開きは再起動後も保存する。仕様5.1と6.2の矛盾は前者を採用。ネイティブ版専用のApplication Support JSONへ保存する（以前のネイティブ版のUserDefaultsは初回のみ取り込む）。閲覧位置・最近使った項目はメモリ内だけに保持する。
- macOS 26以降、arm64、仮Bundle ID `dev.tris.magv-native`。正式な配布・名称・Intel対応は未決定。
- App Sandboxを維持。名前変更に必要なユーザー選択ファイルの読み書き権限を有効化。ファイル単体の選択を親フォルダへの許可とみなさず、必要なフォルダをNSOpenPanelで選び直す。起動中だけ権限を保持し、bookmarkの永続化は行わない。
- 入れ子アーカイブは仕様2.3の対象外を採用する。4.3の「可能であれば」は今回含めない。
- GIF／アニメWebPは先頭フレーム。HEIC／TIFFも拡張子を受け付けるが、追加のデコード検証が必要。

## 現時点の制限

1. アーカイブはヘッダーの一覧と安全性を確認してから、表示に必要な画像だけを展開する。ソース情報は最大3件、展開ファイルは全体2GiB以内でページ単位のLRU管理。RAR5は前方向の展開状態を維持するが、solidの未展開ページへの遠い移動や、破棄済みページへの後戻りには前方データの再解凍が必要になる。実漫画／RAR solidでの性能保証は継続課題。
2. 画像キャッシュは通常表示と高解像度ルーペの合計256MiB以内。ルーペにはその内64MiBまでを割り当てる。デコードは直列化し、待機中は表示→ルーペ→先読みの順に処理する。単一デコードの出力は通常128MiB／ルーペ64MiB以内。同一キーを共有し、URL・ファイル識別子・更新日時・サイズ・寸法で識別する。現在の表示が保持する参照やImage I/Oの一時領域は別なので、プロセス全体のメモリ上限ではない。
3. 一時ディスクは現在表示中・キャッシュ保持中・読み込み中の全展開画像を同じ2GiB予算に数え、各チャンクの書き込み前に予約する。参照されていない先読み・古い展開ファイルから解放する。表示やデコード中のファイルはleaseで保護し、解放対象にしない。必要なファイルが保護中のデータと同時に収まらない場合は上限エラーで旧表示を維持する。起動時は専用領域の識別済み・非ロックの孤立フォルダだけを清掃する。
4. 選択画像の親フォルダが読めない場合は、その画像だけを表示する。ファイルメニューの「画像フォルダへのアクセスを許可…」から画像全体を再読込できる。兄弟切替・名前変更には「同階層フォルダへのアクセスを許可…」も使用する。異なるフォルダの選択は拒否し、キャンセル時は現在の表示を維持する。
5. ヘッダーで分かるエントリ数・申告サイズ・不正パス・暗号化は一覧取得時に検査する。未訪問の画像の寸法・破損・実展開量は読み込む時点で検査する。画像メタデータが読めない位置はエラー枠として残す。CRC／展開量／寸法上限のエラーは、オープン中なら前の本、ページ移動中なら前のページを維持して通知する。
6. 表示設定とウィンドウ位置は`Application Support/dev.tris.magv-native/settings.json`（Sandbox時はアプリコンテナ内）へschemaVersion=1で原子的に保存。閲覧位置・最近使った項目は保存しない。破損・未知バージョンは既定値、無効なウィンドウ座標は既定配置へ戻す。
7. 旧アプリの設定・データ・アイコンは変更・取り込みしていない。移植コードの正式ライセンス、名称、署名、公証は配布前に決める。同梱依存物の著作権表示はアプリの`ThirdPartyNotices.txt`に含める。

## 第3段階の追加検証と実装方針

- 兄弟ソースは操作時にも再列挙する。前後は循環せず、空フォルダは通知して現在の本を保持する。表示中の候補が削除された場合は通知して一覧を更新し、その操作では別候補へ飛ばさない。ランダムは現在以外から直接選ぶ。
- リネームは`renamex_np(RENAME_EXCL)`で同階層の移動を行い、存在する宛先を上書きしない。同時競合でも`_`を追加して再試行する。元の最後の拡張子と大文字小文字を維持する。ファイルの識別子・サイズ・更新時刻が読込時から変わっていた場合は開き直しを案内する。
- 上書き禁止付きrenameが使えないボリュームでは、危険なフォールバックをせず日本語のエラーを返す。検証した一時フォルダ以外の外部／ネットワークボリュームでの動作は未確認。[Appleの対応能力の説明](https://developer.apple.com/documentation/foundation/urlresourcevalues/volumesupportsexclusiverenaming)
- 変更後はタイトル、位置履歴、最近使った項目、兄弟一覧を更新する。展開画像はUUIDの一時URLで保持しているため、名前変更だけではキャッシュ・画像・ページ位置を破棄しない。変更中の外部オープンは最新1件を待機させ、ファイル操作が終わってから開く。
- 名前入力はAppKitのシート。名前本体を全選択し、拡張子と前後ソース名を表示する。独自フィールドエディタでReturn前のIME変換状態も確認し、変換確定のReturnでは実行しない。失敗理由をシート内に表示し、入力を維持する。
- Web検索はURLComponentsで検索語を組み立て、ASCIIハイフンだけを空白に変える。`+`を含む記号や日本語のURLエンコードをテスト。ファイル内容を送信する実装はなく、明示した検索操作だけが既定ブラウザを開く。
- ウィンドウは通常時の外枠を保存する。フルスクリーン中のサイズを保存せず、復元時とスクリーン構成変更時にサイズ・位置をvisibleFrame内へ補正する。閉じる／終了時は保留中の保存を確定する。
- フォルダ許可の応答はソースURLと要求IDが一致する場合だけ使用する。テキスト入力／シート中は閲覧キーと閲覧メニューを無効化する。現在の本と最近使った20件に不要な選択権限は解放する。
- コア追加テスト: 種類別兄弟一覧・自然順、端とランダム、複数ドット／日本語／競合／同時リネーム、不正名、外部置換、権限範囲のパス境界とシンボリックリンク、検索URL、モニター切断／巨大サイズ／無効座標、JSON保存／破損／未知バージョン。
- セッション追加検証: 兄弟への移動と再訪位置、空／削除済み候補、リネーム後のタイトル・位置・履歴・一時画像、!付与競合、古い権限応答、最近使った画像フォルダの閲覧位置、不要な権限の解放、IME送信ガード、表示設定の保存と履歴を復元しないこと。
- 別Bundle IDの検証用アプリをローカル署名でビルドし、`app-sandbox`と`user-selected.read-write` entitlementを確認。アプリの起動は確認できたが、UI自動操作ツールがシステムのファイル選択ダイアログへパスを入力できず、親フォルダの権限付与→切替／リネームの実操作は未検証。手動での日本語IME・名前変更シートの表示／操作、ウィンドウの閉鎖・再表示・モニター実変更も継続検証が必要。

## 第4段階の実装・検証

- 自動再生は初期5秒、0.5〜100,000秒の0.5秒刻み。表示メニュー、上端の開始／停止、プリセット、任意入力シートとステッパーを用意。不正値は入力を保ってエラーを表示する。設定はセッション内のみ。
- ContinuousClockで1回ずつ待ち、ページのデコード完了後から次の間隔を開始。手動移動・直接指定・モード／開き方向・間隔変更では待ち直す。最終画像を含む表示、画像エラー、ソース切替、名前変更開始、ウィンドウ閉鎖で停止する。閉鎖中は再開不可。スリープ中は待機を取り消し、復帰後に新しい1間隔を待つ。
- ルーペは初期OFF、中クリック・表示メニュー・上端ボタンで切替。600×600pt、表示画像の8倍。左右配置・実画像の余白・EXIF補正後の縦横・Retina倍率を考慮する。キャンバス内でクリップし、ページバーと操作部を覆わない。画像外／非アクティブ／メモリ圧迫中には表示しない。
- ルーペ用画像は元画像から必要な解像度で別途縮小デコードし、総量256MiB以内のうち64MiBまで保持する。巨大画像ではこの枠に合わせて解像度を下げる。ポインター移動だけでは同じ画像を再デコードせず、別画像／ページ変更／リサイズ時の古い結果を反映しない。
- ページ移動では操作の移動先と描画済みページを分け、次の表示の全画像のデコードが完了するまで現在の描画を保持する。見開きの画像・配置・エラー枠をまとめて切り替え、連続移動で取り消された描画は反映しない。準備中の旧表示ではルーペを停止する。保持するのは直前の表示1件で、切り替え時には新旧画像が一時的に共存する。
- 現在ページの前後各2枚を先読みし、その後で明示的なフォルダ許可の範囲内にある前後ソースを低優先度で読む。許可を求めるダイアログは先読みから出さない。先読み失敗は現在ソースのエラーにしない。
- SourceCacheは同じソースの同時要求を共有し、アーカイブの二重展開を防ぐ。ファイルの置換、サイズ／更新時刻、フォルダ内の画像追加・削除・更新で失効する。リネームでは展開済みデータを新URLへ引き継ぐ。
- メモリ警告では先読みとルーペを破棄し、criticalでは保持キャッシュも解放する。表示中の画像は維持し、normal通知まで新しい先読みを抑制する。進行中のデコードは最大1件で、終了した古い結果は破棄する。
- 通常終了では所有する一時展開を清掃する。異常終了後は専用マーカーとflockで孤立分を確認する。他プロセスがロック中のフォルダ、シンボリックリンク、不明な内容は清掃対象外。
- 追加コアテスト: 間隔の境界／非数／刻み、余白／見開き／リサイズ／Retinaのルーペ座標、全体バイト予算と解放、失敗時の予約解放、孤立キャッシュとロック・マーカー・リンク保護、同時展開共有、外部置換・フォルダ更新、LRU、リネーム後の展開再利用、画像の共有・メモリ圧迫・単体デコード予算。
- セッションスモークでは制御可能な時計を注入し、取消済みの待機を意図的に遅れて完了させる。自動送りは1回だけ、末尾で停止、手動移動・直接指定・モード／方向・間隔のリセット、スリープ復帰、入力中の中断、失敗したソース切替、画像エラー、名前変更、閉鎖／再表示、ルーペの古い結果破棄とメモリ圧迫を検査。
- 2026-10-18: ページ移動時に描画用画像を先に消していたため起きる暗転を修正。単体／見開き・連続ジャンプ・リサイズ・画像エラー・アーカイブの取消／ソース切替を検査し、`test.sh --ui` では色の異なる合成ページを実際のCanvasViewで描いて移動直後の画像一致と完了後の画像切替を確認した。52件のコアテスト、セッション／名前変更シートのスモーク、Debugビルドが成功。
- ローカル署名の別Bundle ID／Sandbox有効のRelease検証アプリで、NSOpenPanelからZIPを開き、ページ表示と追加メニューの存在を確認。その後UIツールがメニュー項目の無効な要素IDを返し、スクリーンショットも取得できなかった。ルーペの見え方・中クリック、メニューでの再生／間隔入力、チェック同期は実画面で未検証。

## 大容量アーカイブの段階読み込み（2026-10-18）

- `ArchiveReader.index`で自然順の一覧を取得し、`ArchiveImageStore`が要求された画像を展開する。初回は表示モードと縦横に必要な1〜2枚だけを準備する。単体表示・先頭が横長の場合は2枚目を待たない。履歴の開始位置から直接準備できる。
- ZIPは圧縮データをスキップして必要なエントリを読む。RAR4の非solidも前方データをスキップする。RAR5はカーソルを保持し、前方向への移動ではsolid辞書を継続利用する。途中のデータを処理する必要があっても、要求していない画像をディスクへ書き出さない。
- 同梱libarchiveへ一覧取得専用の `rar5:magv-index-only=1` を追加。solidデータを一覧段階で全解凍する経路を避ける。このモードは画像データの読出しを明示的に拒否し、通常の展開器のCRC検査・辞書処理は維持する。パッチを保存し、上流ソースのハッシュ確認→パッチ適用→XCFramework作成までをオフラインで再ビルドできるようにした。
- 展開ファイルの容量とLRUを全ソースで共有する。ファイルを参照中の `LoadedSource` は必要なファイルのleaseを保持する。キャッシュから外れた画像の寸法は保持し、再訪時に画像データだけを再展開する。SourceCacheのソース保持とページのファイル保持を分離した。
- 一般の利用側は、アーカイブの `ImageEntry.fileURL` にアクセスする前に `LoadedSource.preparingImages`／`preparingPage` を呼び、デコード完了まで戻り値を保持する。ImageCacheには `retaining:` でも渡し、取消通知後も実際のデコーダーが終了するまでファイルを保護する。URLが一覧にあることだけでは、その画像がディスクに存在するとは限らない。
- 見開き・前ページの強制単体・最後への移動を決める前に、必要な近傍の寸法を取得する。連続したページ送りは順に処理し、直接ジャンプは最新の要求へ置き換える。取消・ソース切替・閉鎖後の結果は反映しない。読込に150ms以上かかるページでは、前の表示を保ったまま進行表示とキャンセルを出す。
- 同じ画像への要求を共有し、共有相手が残っている処理は一方の取消だけで停止しない。途中で止まったファイルは破棄して予約容量を戻す。リネーム時は展開器の入力URLも引き継ぐ。
- 追加検証: 初期表示が後方の巨大画像を展開しないこと、全件の展開量より小さいキャッシュで40ページを読み進めて先頭へ再訪、同時12要求の共有、同名エントリの区別、不正な後方ヘッダー、UTF-8／CP932／ZIP64、RAR4／RAR5とsolidの選択読込・再訪・内容照合、途中取消のファイル／容量解放、単体／横長で2枚目を待たないこと、先読み取消後も動作中のデコーダーが参照するファイルをLRU削除しないこと、古い表示要求をデコード待機列から取り消すこと。
- セッションスモークでは、縦横混在かつ物理格納順が逆のZIPを生成し、遅延した寸法取得でも既存のPageNavigatorと同じ結果になることを確認する。連続送り、連続ジャンプ、ページ取消、読み込み中の別ソースへの切替、段階読み込み中のスライドショーと末尾停止も検証対象に加えた。

### 大容量ベンチマーク

`./scripts/benchmark.sh --large` の最終版Releaseコア処理の測定例。2000×3000pxの同一内容の合成JPEG 300枚、ZIP前の画像合計476.30MiB。従来相当の比較経路は、全件展開・全画像の寸法取得・先頭見開きデコードを行う。同一プロセス内で比較し、OSのファイルキャッシュは消去していない。GUI描画・Sandbox・実漫画を含む体感速度の測定ではない。

| ZIPの処理方式 | 読込＋先頭見開きデコード | 初期表示までの展開量 |
| --- | --- | --- |
| 従来相当の全件展開 | 1,379.49ms | 476.30MiB |
| 必要ページの展開 | 131.25ms | 3.18MiB |

同じ入力で初期表示準備は約10.5倍速くなり、初期展開量は約99.3%減った。次見開きを先読みした後の展開量は6.35MiB、キャッシュ済み次見開きの準備・デコードは0.157ms。ヘルパープロセス全体の最大RSSは43.69MiBであり、GUIアプリの常用メモリ値や方式ごとの独立したメモリ比較ではない。

予備測定した300枚・1,214.49MiBの入力でも、全件展開相当3,127.67msに対し必要ページのみ173.47ms、初期展開量は8.10MiBだった。solid RARの遠方移動、実漫画、長時間の反復操作は引き続き別途測定する。
